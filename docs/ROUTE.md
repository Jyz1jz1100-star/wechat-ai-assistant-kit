# 为什么走这条路，以及别的路为什么不通

这段是选型依据。想省时间可以只读表格最后一行。

## 候选路线（截至 2026-09 的核实结果）

| 路线 | 能不能用 | 卡在哪 |
|---|---|---|
| **公众号 + 服务器回调** | ❌ | 微信的域名管理要求所有回调域名 **ICP 备案 + HTTPS**，不接受 IP。`trycloudflare`/ngrok 这类域名注册不进去。个人主体只能注册订阅号且无法微信认证，客服消息还收紧到「用户发消息后 48 小时 / 5 条」 |
| **微信客服 API** | ❌ | 需要企业微信并已完成**企业认证**，个人开不了 |
| **PC 客户端 hook / DLL 注入** | ❌ | WeChatFerry 仓库已归档；wxhelper、chatlog 全部钉死 3.9.x。而 3.9.11/3.9.12 现在登录直接报「版本过低」，微信 4.x 又换了架构 |
| **付费 iPad / 协议网关** | ⚠️ 极不推荐 | 逆向协议是风控识别的主要对象，封号率最高；价格不透明；2026 年有多个同类项目在关停 |
| **PC 客户端 UI 自动化** | ⚠️ 不满足需求 | 只能驱动电脑上的那个窗口，**手机上没法用**；且各版本对客户端版本号卡得很死 |
| **`Tencent/openclaw-weixin`** | ✅ | 出站长轮询 → 不需要公网服务器/域名/备案/穿透/注入。腾讯官方 org，MIT |

## 这条路的技术要点（都实测过）

- **单向出站**：连接由你的机器主动拨出，微信服务器不需要能访问你。备案墙、内网穿透、
  TLS 证书这些麻烦一起消失。这是全套方案简洁性的来源。
- **扫码换的是独立 Bot 账号**（协议里的 `ilink_bot_id`），不是接管你扫的那个微信号。
  你从自己的微信跟这个 Bot 单聊。**不需要第二个微信号。**
- **天生异步**：收消息走 `getUpdates` 长轮询，发消息走独立的 `sendMessage`，
  所以公众号那个「5 秒内必须回复完」的限制**不适用**。模型想 12 秒也没关系。
- **`sendTyping`** 能在思考期间显示"正在输入"，把等待感处理掉。不需要"先回占位再补发"
  那套复杂度。
- **限流是真实的**：协议文档记载 `errcode -14` 会让账号会话暂停一小时。表现为"突然一小时
  都不回"。别把它当故障去反复重试，那只会延长惩罚。
- **登录命令不幂等**：重复扫码会在本地留下多份凭据条目。不影响使用（会话按账号隔离），
  但别指望重扫能"刷新"旧条目。

## 风险，不打折

- 这个 iLink bot 协议**没有公开契约**。网上"官方开放"和"禁止第三方使用"两种说法互相矛盾，
  我没找到腾讯的正式条款。仓库是 MIT，但"官方发的工具"不等于"签了 API 协议"。
- 封号的公开共识是看**行为**：高频、秒回、24 小时在线、群发 —— 而不是看用了哪个工具。
  自用单聊低频落在相对安全的区间，但相对安全不等于零风险。
- **不要用你最在乎的微信号承担这个风险。**
- 合规：纯个人自用不触发生成式 AI 的备案义务；一旦对外提供服务就会触发
  （《生成式人工智能服务管理暂行办法》《人工智能生成合成内容标识办法》）。
  别拿它做面向公众的机器人。
